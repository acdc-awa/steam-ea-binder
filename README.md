# Steam / EA 账号绑定工具

Windows 下的桌面自动化工具：按顺序读取一批 Steam / EA 账号，自动完成 Steam 登录 → 启动《战地 1》→ 在 EA 客户端中填邮箱、密码、两步验证码，最终点击“绑定 Steam”，实现 Steam 账号与 EA 账号的批量关联。

工作方式是**真实模拟键鼠 + 屏幕模板识别**（OpenCV 截图匹配按钮/输入框，再移动真实鼠标去点击），因此对运行环境（尤其是窗口状态）有一定要求，见下文[对窗口和桌面的要求](#对窗口和桌面的要求)。

---

## 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11（依赖 win32gui、win32api、winreg 等 Windows API，不支持 macOS / Linux） |
| Python | 3.10 及以上 |
| 权限 | **必须以管理员身份运行**才能启动绑定（需要关闭 `EABackgroundService` 服务和 EA 后台进程）；非管理员只能读取和浏览账号 |
| 依赖库 | 见 `requirements.txt`：numpy、opencv-python、Pillow、pywin32、psutil、PySide6（Qt 界面可选） |
| 客户端 | 已安装 Steam 客户端、EA 桌面应用；绑定账号需能启动《战地 1》（通过 `steam://rungameid/1238840` 拉起 EA 登录窗口） |

## 安装与启动

```bash
pip install -r requirements.txt
```

```bash
python main.py      # Tk 界面（默认，无额外依赖）
python qt_main.py   # Qt 界面（需要 PySide6，二选一即可）
```

两个界面功能相同，可在工具栏用“切换到 Qt / 切换到 Tk”按钮互相切换（流程运行中不允许切换）。窗口标题会显示当前是否为管理员权限；若以非管理员启动，程序会弹窗提示，读取账号不受影响，但点“启动/批量启动”会被拦截。

## 代码结构

入口脚本放在仓库根，实现代码都在 `binder/` 包里，`main.py` 与 `qt_main.py` 需要互相拉起，
所以两者必须留在同一层目录。

```
main.py                 Tk 界面入口（默认）；账号模型、CSV 读写、子进程入口也在这里
qt_main.py              Qt 界面入口（需要 PySide6），复用 main.py 里的账号模型与子进程入口
binder/
    paths.py            唯一的路径基准：仓库根、资源目录、日志与调试输出目录
    app_logging.py      info.log / error.log 的日志器
    app_runtime.py      管理员权限判断等运行时信息
    automation/         桌面自动化底座
        win_utils.py        窗口查找与前台激活
        mouse_motion.py     真实鼠标轨迹移动
        process_utils.py    进程/服务查询与关闭
        credential_cleanup.py  Steam / EA 登录态清理
        window_capture.py   窗口截图（PrintWindow）与模板匹配
        error_text_detect.py  登录页红字错误提示检测（账密有误的视觉证据）
        debug_trace.py      调试截图与逐帧日志落盘
    flows/              绑号流程
        binding_flow.py     单账号编排：Steam 阶段 → EA 阶段 → 收尾清理
        steam_flow.py       Steam 登录、EULA、启动战地 1
        ea_flow.py          EA 登录、2FA、关联 Steam 与结果校验
        errors.py           业务异常：AccountInfoError（账号资料有误）
assets/img/{ea,steam}/  模板图片（像素匹配用，改界面语言/缩放会让它失配）
```

运行时产物都在仓库根，且已被 `.gitignore` 排除：`info.log`、`error.log`、
`debug_capture/`、`*.csv`（含明文密码）、`*.binderbak`。

> 注意：所有模块都必须从 `binder/paths.py` 取路径。代码分层之后，各自写
> `Path(__file__).parent` 会指向模块自己所在的子目录，而不是仓库根。

## 如何读取账号信息

账号全部来自一个 **CSV 文件**，程序本身不联网获取账号：

1. 点击工具栏 **“读取账号”** 按钮；
2. 在文件对话框中选择 `.csv` 文件（只接受 `.csv` 后缀）；
3. 读取成功后账号显示在表格中；有格式问题会弹出警告（最多列出 10 条）。

### CSV 格式

| 列序 | 列名（示例） | 必填 | 说明 |
| --- | --- | --- | --- |
| 1 | Steam 账号 | 是 | Steam 登录名 |
| 2 | Steam 密码 | 是 | |
| 3 | EA 邮箱 | 是 | EA 登录邮箱 |
| 4 | EA 密码 | 是 | |
| 5 | EA 2FA 16位码 | 是 | EA 两步验证密钥（Base32，即绑定验证器时显示的那串字符），程序据此本地生成 6 位 TOTP 验证码；空格、连字符会被自动忽略，大小写不敏感 |
| 6 | 是否已绑定 | 否 | 只有值为 `True`（不区分大小写）才视为已绑定，其余值一律按未绑定处理；省略该列则全部按未绑定 |
| 7 | 绑定进度 | 否（程序自动写入） | 程序实时写入的当前状态（如 `Steam登录中`、`已绑定`、`失败：…`），用于断点续行恢复显示 |
| 8 | 跳过状态 | 否（程序或人工写入） | 非空表示该账号被跳过，值只能是 `信息有误` 或 `暂不登录`（也接受 `账号信息有误`、`暂时无法登录`、`暂时跳过`）。被跳过的账号不进入批量/“下一轮”，详见[账号信息有误与跳过标记](#账号信息有误与跳过标记) |

示例：

```csv
Steam账号,Steam密码,EA邮箱,EA密码,EA2FA16位码,是否已绑定,绑定进度,跳过状态
steamuser1,P@ssw0rd1,ea1@example.com,EaP@ss123,JBSWY3DPEHPK3PXP,False,Steam登录中,
steamuser2,P@ssw0rd2,ea2@example.com,EaP@ss456,KRSXG5CTMVRXEZLU,True,已绑定,
steamuser3,P@ssw0rd3,ea3@example.com,EaP@ss789,KRSXG5CTMVRXEZLU,False,账号信息有误：EA密码,信息有误
```

读取规则（见 `main.py` 的 `load_accounts`）：

- **编码**：自动尝试 `utf-8-sig`（带 BOM 的 UTF-8）和 `gb18030`（GBK），都不行才报错；
- **表头可有可无**：第一行若前 6 列中有 ≥2 个命中已知表头名（`steam账号 / steam密码 / ea邮箱 / ea账号 / ea密码 / ea2fa16位码 / ea2fa / 2fa / 是否已绑定 / steamaccount / steampassword / eaemail / eapassword / isbound / bound` 等，忽略大小写和空格），则跳过该行；没有表头则直接从第 1 行读数据；
- **少于 5 列**的行跳过并警告；全空行、5 个字段全空的行直接跳过；
- **第 8 列只认已知关键字**：如果你在那列写了别的内容（自己的备注等），程序会忽略它并给出警告，不会把账号当成已跳过——否则一个笔误就会让本该跑的账号被悄悄跳掉；
- 表格默认**掩码显示**密码和 16 位码（2FA 只显示末 4 位），点“显示密码/16位码”按钮切换明文。

### 表格右键菜单

在账号行上**右键**：

- **启动** — 单独运行这个账号的绑定流程（已绑定或被跳过的账号置灰，点击会被弹窗拦截）；
- **标记为已绑定** — 一键把该账号标成“已绑定”并立即写入 CSV，批量和“下一轮”从此跳过它；
- **标记为信息有误** — 人工把账号标成资料有问题并写入 CSV，后续轮次自动跳过；
- **标记为暂不登录** — 人工标记“这个账号暂时不处理”，后续轮次自动跳过；
- **取消跳过标记** — **唯一**能清掉跳过状态的入口（见下节）；
- **修改** — 弹窗编辑该行字段，可改绑定状态；
- **删除** — 从列表移除（需确认）。

跳过标记的三项在**批量运行期间也能用**：标记本身只是元数据，不碰正在跑的流程，所以发现某个账号资料不对时可以立刻把它从后续轮次里摘掉。

- **进度恢复**：CSV 若带第 7 列“绑定进度”，读取后会直接显示在“当前绑号进度”列；进度为“已绑定”的行自动视为已绑定，实现断点续行。

> **进度会实时写回 CSV**：每当某行的绑号进度变化（含绑定成功、被自动标记“信息有误”）或跳过标记变化，程序会把该行的“是否已绑定”“绑定进度”“跳过状态”三列写回原 CSV（保留原编码，缺列自动补），详见[断点续行](#断点续行进度写回)。界面上的“修改账号”只可能带动这几列写回——改的密码等字段内容**不会**写入 CSV（字段请直接在 CSV 里改），“删除行”也只删界面列表、不改文件，下次读取该行仍会出现。

## 如何运行绑定

- **单个账号**：右键账号行 → “启动”。
- **批量（按轮运行）**：在工具栏 **“每轮数量”** 框填入 N（从上到下取前 N 个未绑定的账号），点 **“批量启动”** 开始第 1 轮。账号按列表顺序逐个执行，同一时间只跑一个；**一轮跑完 N 个后自动暂停**，状态栏显示“第 X 轮完成 · 剩余 … · 点「下一轮」继续”，再点 **“下一轮”** 按钮接着跑下一批 N 个，直到没有待处理账号。

绑定过程中“当前绑号进度”列会依次显示状态，例如：

```
批量等待中 → 清理登录态中 → Steam登录中 → 校验Steam登录中 → Steam登录成功
→ 启动游戏中 → Steam阶段完成 → EA启动中 → EA切换账号中 → EA输入邮箱中
→ EA输入密码中 → EA验证身份中 → EA输入验证码中 → EA绑定Steam中 → 校验关联结果中 → 已绑定
```

账号资料有误时会提前结束，状态显示 `账号信息有误：EA密码` 这类带字段名的文案（详见[账号信息有误与跳过标记](#账号信息有误与跳过标记)）。

已绑定账号会被识别为 `检测到已绑定，收尾中` 后直接进入 `已绑定`，不再空等超时。

被跳过的账号不会进入批量/“下一轮”，状态栏的“剩余 N 个”也不含它们。

失败时显示 `失败：<异常类型>: <原因>`。成功后该行“是否已绑定”变为“已绑定”，且后续批量会自动跳过它。

### 账号信息有误与跳过标记

账密或 2FA 码偶发写错时，EA 会在登录页显示一行红字。程序据此**立刻停下并跳过这个账号**，而不是一直重试到卡住：

- **自动标记（只发生在 EA 阶段）**：登录类页面（邮箱 / 密码 / 验证码 / 验证身份）的输入框下方连续两帧出现红字，即判定账号资料有误，进度列显示 `账号信息有误：EA密码` 这类带字段名的状态，同时把第 8 列写成 `信息有误`，后续轮次自动跳过它。
  判定不看文案只看颜色（`binder/automation/error_text_detect.py`），所以 EA 改文案、换语言都不影响；区域限定在“输入框下方”，因此 EA 那个红色的 logo 不会被误判。
- **重复次数上限兜底**：同一个页面连续重复执行 3 次仍未跳转（`ea_flow.LOGIN_STRATEGY_MAX_ATTEMPTS`），就按普通失败上报并换下一个账号。这条不依赖红字检测，即使 EA 改版让红字判定失效也不会再无限空转。
- **Steam 侧只记日志**：Steam 主窗口里红色元素太多（促销横幅、库里角标），整窗扫描做不到 EA 那种精度，所以只把线索写进 `info.log`（提示“如确认请右键标记为信息有误”）。唯一会自动标记的情况是 **Steam 拒绝切换到目标账号**（`verify_steam_login` 返回 `stale`）——那时账号确实没登录成功。

**标记只进不出**：程序可以给账号加跳过标记，但**永远不会自动清除**。清标记只有一个人工入口——右键 **“取消跳过标记”**。这是刻意的：标记是给你看的待核对清单，如果程序会自动清，一次网络抖动的误判就会把“待核对”悄悄变回“没问题”。同理，**修改账密不会自动取消标记**（修改对话框里会提示这一点），改完密码后要自己右键取消。

被跳过的账号在表格里整行显示为橙色，与“已绑定”的灰色区分开——一个是完成，一个是待核对。

**手动标记的用途**：自动判定只覆盖“EA 页面出现红字”这一条证据。如果你的情况是别的（Steam 账密错、账号被临时封禁、2FA 密钥还没拿到），就用右键 **“标记为信息有误”** 或 **“标记为暂不登录”** 手动摘掉它，让批量继续往下跑。

如果红字判定在你机器上误判（把好账号标成信息有误），先把 `ea_flow.LOGIN_ERROR_DETECTION_ENABLED` 设为 `False` 关掉它，重复次数上限仍然兜底；或者调大 `LOGIN_ERROR_REGION_VERTICAL_SPAN` / `LOGIN_ERROR_REQUIRED_HITS` 再试。

每个账号开始时会**先退出当前已登录的 Steam 并清空 Steam / EA 的登录态**，全部绑定完成后会**关闭 Steam**，并结束《战地 1》游戏本体（`bf1.exe`）、EA 反作弊启动器、`EABackgroundService` 进程及对应 Windows 服务 —— 所以批量运行期间不要用这台电脑玩游戏。关游戏本体的顺序在反作弊之前：游戏还在跑的话会把被关掉的反作弊重新拉起来。失败中止时同样会收掉这些进程。

日志写在程序目录下的 `info.log`（运行信息）和 `error.log`（错误堆栈）。

## 已绑定账号的识别与回避

**自动识别规则**（两条独立路径）：

1. **从未出现登录页**：进入 EA 阶段后，如果一直没出现邮箱 / 密码登录页，
   而是直接拉起了 `EAAntiCheat.GameServiceLauncher`，判定该账号已经绑定过。
   为避免把“登录页还没渲染出来”误判成“已绑定”，进入 EA 阶段后有 **15 秒宽限期**
   （`ea_flow.BOUND_DETECTION_GRACE_SECONDS`），且信号需持续 **3 秒**稳定存在。
   注意：判断信号只认反作弊启动器，不认游戏本体 `bf1.exe` —— 后者在 Steam 阶段
   就被拉起，与是否绑定无关。
2. **2FA 之后没有关联页**：填完 2FA 后，如果在 20 秒内没有出现“关联 Steam”页，
   而是直接拉起了反作弊启动器，同样判定为已绑定（账号已关联，无需再次关联）。

**关联前必须确认登录身份**：点“关联账号”之前，程序会先确认本次**确实出现过 EA 登录页**
（即邮箱/密码是我们自己填进去的）。如果没出现登录页就直接到了关联页，说明 EA 里还登录着
别的账号，此时点“关联账号”会把本行的 Steam 账号绑到那个不属于本行的 EA 账号上，而且界面上
完全看不出异常——所以这种情况会直接中止并提示先让 EA 退出登录，而不是硬点下去。
（EA 的账号就是邮箱，所以“本次用 CSV 里的邮箱登录过”即等价于“登录的是目标 EA 账号”。）

**关联结果校验**：点击“关联账号”后，程序会等待反作弊启动器启动来确认绑定真的生效
（最长 90 秒），而不是“点一下就算成功”。超时会报失败并提示可手动标记。
如需退回旧的“点击即成功”行为，把 `ea_flow.LINK_VERIFY_STRICT` 设为 `False`。

**点击确认与重试**：关联页这一下是全流程唯一一次“孤立的第一次点击”（邮箱、密码、
验证码页都是先点输入框再点按钮，所以窗口早被激活了），最容易被系统当成“激活点击”
吃掉——鼠标明明点在按钮上，页面却不动。因此点击前会先确认 EA 窗口真的到了前台
（`win_utils.activate_window` 会校验 `GetForegroundWindow`，失败重试 3 次），点击后
会重新截图确认关联页是否跳转，没跳转就重新点击，最多 3 次
（`ea_flow.LINK_CLICK_MAX_ATTEMPTS`），之后才进入 90 秒等待。日志里会记录每次点击的
实际屏幕坐标、页面是否跳转、以及 90 秒等待的进度，另外点击后会额外落一张
`*_link_clicked_printwindow.png` 截图，便于事后判断页面到底有没有反应。

**回避**（已绑定账号会在以下位置被跳过或拦截）：

- “批量启动 / 下一轮”选取时直接过滤，不会进入任何一轮；
- 右键“启动”菜单项置灰，点击也会被弹窗拦截；
- 表格整行灰色显示；
- 结果写回 CSV，下次读取继续回避（跨会话有效）。

**被跳过（账号信息有误 / 暂不登录）的账号走同一套回避**：选取时过滤、右键“启动”置灰并被拦截、整行橙色显示、写回 CSV 第 8 列跨会话有效。区别只在“谁把它标上去的”——已绑定由自动识别或人工确认，跳过标记由 EA 红字自动判定或人工右键。

**手动标记**：右键账号 → **“标记为已绑定”** → 确认，立即写入 CSV。用于补救自动识别漏判的账号，例如关联按钮其实点成功了、但收尾超时被报成“失败”——标记后后续轮次全部跳过。想改回“未绑定”，用右键“修改”里的“是否已绑定”下拉框。

## 断点续行（进度写回）

进度和绑定结果会**实时保存回 CSV 文件**，中途关程序、崩溃都不用从头再来：

- 每当一行的进度变化，程序会在约 0.15 秒内把该行的 **“是否已绑定”**（成功=`True`）和 **“绑定进度”**（当前状态文本）写回原 CSV；关闭程序窗口前还会强制写一次。极端情况（瞬间断电/强杀进程）最多丢最后 0.15 秒内的状态，该账号下次会重跑。
- **续行步骤**：
  1. 关闭程序（中途崩溃、重启电脑同样适用）；
  2. 重新启动，点“读取账号”选择**同一个 CSV**；
  3. 已绑定的行显示“已绑定”，批量/下一轮不会再选它；上次停在半路的行会显示当时的进度（如 `EA输入密码中`、`失败：…`）；
  4. 照常点“批量启动 / 下一轮”继续。
- CSV 只有 5 列也能用：程序会自动补第 6/7/8 列；有表头但缺列名时会自动补上 `是否已绑定`、`绑定进度`、`跳过状态`，文件编码保持原样（UTF-8 / GBK 均可）。
- **写回失败**最常见的原因是 CSV 正被 Excel/WPS 打开占用，失败会记入 `error.log`；关掉占用程序后，后续状态会继续正常写入。
- **运行期间不要用 Excel 编辑该 CSV**：行位置一旦变动，写回时按“行号 + Steam 账号”校验不通过会跳过该行（不会写错行，但这次进度会丢）。

## 如何中途暂停

**暂停的主方式是“按轮运行”**：每轮只处理 N 个账号，跑完自动停下，由你人工决定何时继续。

- **每轮数量 = N**：一轮处理完 N 个账号后，批量子进程自动结束，即“自动暂停”——不会再启动新账号。
- **暂停后的状态**：状态栏显示 `第 X 轮完成 · 剩余 Y 个 · 点「下一轮」继续`，**“下一轮”** 按钮点亮。
- **继续下一轮**：点 **“下一轮”**（或“批量启动”，效果相同），会自动跳过已绑定账号、从剩余账号里再取 N 个作为第 X+1 轮。
- **全部处理完**：状态栏显示“没有待处理账号了”，“下一轮”按钮置灰。
- 上一轮**失败**或被**中止**的账号仍算待处理，下一轮会自动重试。

**紧急停止**（不等当前账号跑完）：

- **批量运行中**：点红色 **“中止”** 按钮，立即终止批量子进程——正在跑的账号被**强杀中断**（可能停在半登录状态），还没轮到的标记为“已中止”，已“已绑定”的行不受影响。中止后状态栏同样提示剩余数量，“下一轮”可继续。
- **单账号运行中**：没有中止按钮，只能等它跑完，或直接**关闭程序窗口**（关闭时会自动终止所有子进程）。
- **想尽量干净地停下来**：等当前账号进度走到“已绑定”再点“中止”，这样只取消排队中的账号，不会留下跑了一半的账号。

## 登录态清理（跨账号不串号）

每个账号开始前和结束后，程序都会**强制清空 Steam 与 EA 的登录态**，避免下一个账号沿用上一个账号的会话：

- **Steam**：先结束 `steam.exe` 与 `steamwebhelper.exe` 并确认主进程退出，然后把
  `config/loginusers.vdf` 里各账号的 `AutoLogin` / `RememberPassword` 置 0，
  并删除注册表 `HKCU\Software\Valve\Steam\AutoLoginUser`。原文件会备份为
  `loginusers.vdf.binderbak`。注意：若 Steam 未勾选“在此设备上记住我”，
  它本身就不会保存登录态，这里只是确保即使保存过也不会被下一个账号沿用。
- **EA App**：结束 `EADesktop.exe`、`EABackgroundService`、`EAAntiCheat.GameServiceLauncher`
  以及 `EABackgroundService` / `EALocalHostSvc` 服务，并把
  `%LOCALAPPDATA%\Electronic Arts\EA Desktop\CEF`（EA 的认证 cookie 所在）改名备份为
  `CEF.binderbak`，强制下次重新登录。代价是 EA 每次都要重新登录，这是预期行为。
- **登录身份校验**：Steam 登录后会读 `loginusers.vdf` / 注册表确认当前自动登录的账号
  就是目标账号；若确认仍停留在**上一个账号**，直接判失败并跳过该账号。
  若只是读不到标记（未勾选记住登录），只记警告继续，不会误报失败。
- **Steam Guard**：程序**不处理任何二次验证**。若登录没能完成（例如遇到 Steam Guard），
  会因等待窗口/身份确认超时而失败并跳过该账号。
- **EA 换号页兜底**：若 EA 仍记着上一个账号，登录前会先出现 **Confirm your EA Account**
  这一页（一行上一个账号的 gamertag + 蓝色链接 *Not your account?* + 通栏 CONTINUE
  按钮）。程序会点 **Not your account?** 把上一个账号登出，再走正常登录，状态显示
  `EA切换账号中`。这一页的 **CONTINUE 绝不能点** —— 点下去就是“就用上一个账号关联
  Steam”，正是要避免的串号。所以这里只认标题和链接两个模板，按钮不参与匹配；
  标题命中而链接没命中时宁可超时也不动手。

## 对窗口和桌面的要求

这是最容易出问题的部分，运行绑定时请保证：

1. **窗口不能最小化。** 程序截取的是窗口在屏幕上的可见区域，Steam / EA 窗口一旦最小化，截图直接抛异常（“窗口已最小化，无法截取可见内容”）。
   （唯一的例外是程序**自己**收起来的 Steam 界面，见下面第 2 条——那是刻意的，而且那时已经不需要再读 Steam 了。）
2. **前台只留给 EULA 和 EA，Steam 界面会被收起来。** 全流程只有两个窗口会被主动切到前台：Steam 的 EULA 对话框，和 EA 窗口。Steam 主界面又大又爱抢前台，压在 EA 上就会出现“鼠标点在按钮上、页面却不动”——因为点击落在了 Steam 上。所以 Steam 阶段一结束，程序会把所有标题为 `Steam` 的窗口最小化；EA 窗口出现时再收一遍（启动游戏会让 Steam 自己再弹一次）。这样前台只剩 EA，不需要你手动去关 Steam 窗口。
3. **窗口不能被其他窗口遮挡（已大幅缓解）。** 现在默认用 `PrintWindow(PW_RENDERFULLCONTENT)`
   直接抓窗口自身内容，**不受遮挡和其他 Steam/EA 窗口影响**；只有 PrintWindow 失败或抓到全黑帧时才回退到
   屏幕截取（`ImageGrab`，会被遮挡影响）。如需强制走旧的屏幕截取，设置环境变量
   `STEAM_EA_CAPTURE_MODE=grab`。窗口最小化仍然不行——最小化时无法截取内容。
4. **窗口标题必须精确匹配。** 程序按窗口标题精确查找（忽略大小写）：Steam 窗口标题必须正好是 `Steam`，EA 窗口标题必须正好是 `EA`，带后缀或其他字样的窗口找不到。
5. **运行期间不要碰鼠标和键盘。** 程序移动的是真实光标、发的是真实点击和按键，你一动鼠标就会点歪；也不要让屏幕保护程序、锁屏、休眠触发。
6. **界面语言与缩放要和模板一致。** 按钮/输入框靠 `assets/img/` 下的像素模板匹配（阈值 0.85），Steam、EA 客户端的**界面语言、主题、显示缩放**与模板采集时不一致就会匹配失败。建议 Windows 显示缩放设为 **100%**，客户端保持默认语言。程序已自行启用 DPI 感知来保证坐标一致。
7. **支持多显示器**，窗口可以不在主屏上。
8. **绑定会独占使用这台机器**：每个账号开始前会退出当前 Steam，结束后会关闭 Steam 并杀掉 EA 后台进程/服务，所以批量期间不要同时玩游戏或依赖 EA 后台。
9. **单账号串行执行**，不能多开程序并行绑（会互相抢鼠标和窗口）。

## 调试模板识别（窗口枚举 + 截图 + 匹配分数）

模板识别（OCR）出问题时，开启调试模式可以看到“当前枚举到哪些窗口、每个窗口长什么样、每个模板匹配了多少分”，
全部按**工作顺序**写进 `info.log`，同时把每一帧截图落盘。

开启方式（任选）：

```bash
python main.py --debug-capture                          # 跑绑号流程并记录
python main.py --debug-capture --debug-all-windows      # 额外截图所有可见顶层窗口
python main.py --snapshot-windows                       # 只做一次窗口快照后退出（不跑流程）
python -m binder.automation.debug_trace --all-windows --window-title Steam --window-title EA
```

也可以只用环境变量 `STEAM_EA_DEBUG_CAPTURE=1`。Qt 界面 `qt_main.py` 支持同样的参数。
开启后窗口标题会显示“调试截图已开启”。

| 环境变量 / 参数 | 默认 | 说明 |
| --- | --- | --- |
| `STEAM_EA_DEBUG_DIR` / `--debug-dir` | `<仓库根>/debug_capture/<时间戳>_<pid>` | 输出目录 |
| `STEAM_EA_DEBUG_FRAME_INTERVAL` | `1.0` | 截图落盘的最小间隔秒数；设 `0` 表示每帧都存 |
| `STEAM_EA_DEBUG_ALL_WINDOWS` / `--debug-all-windows` | 关 | 额外枚举并截图所有可见顶层窗口 |
| `STEAM_EA_CAPTURE_MODE` | `printwindow` | 设为 `grab` 强制用屏幕区域截取，便于对比 |

**日志格式**：`[DEBUG][序号] 上下文 | 内容`。序号严格按调用顺序递增，所以日志顺序就是工作顺序；
截图文件名带同一序号，可直接按文件名排序与日志逐条对照。示例：

```
[DEBUG][0001] Steam阶段/acc1 | 全窗口枚举 Steam阶段开始 共 573 个顶层窗口，其中有标题或可见的 128 个：
[DEBUG][0002] Steam阶段/acc1 |   窗口 hwnd=133550 title='Steam' class='Chrome_WidgetWin_1' visible=True iconic=False rect=(672,226,2390,1252) pid=27644
[DEBUG][0007] Steam阶段/acc1 | 窗口枚举 title='Steam' 命中 1 个: hwnd=133550 title='Steam' rect=(672,226,2390,1252) iconic=False
[DEBUG][0008] Steam阶段/acc1 | 截图 EULA_133550_printwindow shape=1718x1026 mean=243.2 文件=0008_EULA_133550_printwindow.png
[DEBUG][0009] Steam阶段/acc1 | 模板匹配 steam_eula_title 阈值=0.85 最高分=0.9312 结果=命中
[DEBUG][0010] Steam阶段/acc1 | 模板匹配 steam_eula_accept_button 阈值=0.85 最高分=0.6180 结果=未命中
[DEBUG][0012] EA阶段/acc1/ea_email_input | 截图 hwnd_133550_printwindow shape=1400x900 mean=240.1 文件=0012_hwnd_133550_printwindow.png
```

**怎么用它定位问题**：

- **“命中 0 个”** → 窗口标题不匹配（标题必须精确等于 `Steam` / `EA`），或窗口被最小化。
- **截图是黑的 / 截到的是别的窗口** → 抓取方式不对：用 `STEAM_EA_CAPTURE_MODE=grab` 跑一次对比，
  或在日志里看是 `_printwindow` 还是 `_grab` 后缀。
- **最高分卡在 0.6~0.85** → 界面语言 / 显示缩放与模板不一致，可考虑降阈值或重做模板。
- **枚举到的窗口列表** → 直接回答“屏幕上到底有哪些窗口”，用来判断是不是有别的同名窗口在抢匹配。

> 注意：调试模式会把**屏幕内容（含窗口里的账号信息）落盘**到 `debug_capture/`，排查完请及时删除。

## 常见问题排查

- **启动被拦，提示需要管理员权限** — 关闭程序，右键 `main.py`（或你的启动方式）“以管理员身份运行”。
- **进度一直停在“Steam登录中”** — 多半是 Steam Guard 或额外验证拦住了（程序走 `steam -noreactlogin -login 账号 密码` 命令行直登，不处理验证码弹窗）。
- **停在“启动游戏中”后失败 / EA 阶段超时** — 战地 1 没能拉起 EA 登录窗口。确认账号能启动游戏、EA 桌面应用已安装并可正常登录。
- **EA 阶段一直识别不到页面** — 按上面第 1、2、5 条检查：窗口没最小化、没被遮挡、语言/缩放与模板一致。
- **排查模板识别** — 用调试模式看窗口枚举、截图和匹配分数（见[调试模板识别](#调试模板识别窗口枚举--截图--匹配分数)）：
  ```bash
  python main.py --snapshot-windows --debug-all-windows   # 先看屏幕上有什么窗口
  python main.py --debug-capture                          # 跑流程并逐帧记录
  ```
- **读取 CSV 报编码错误** — 把文件另存为 UTF-8 或 GBK。
- **界面卡住/崩溃** — 看 `error.log`，里面记录了完整堆栈。
- **进度没写进 CSV** — 看 `error.log` 里的“CSV进度写回失败”，通常是文件被 Excel/WPS 占用或设为只读；关闭占用程序后继续运行即可。
- **账号明明已绑定却一直报失败** — 自动识别依赖“反作弊启动器启动”这个信号；如果 EA 侧页面异常、等不到信号就会超时。右键该账号 →“标记为已绑定”即可永久跳过它。另外若 EA 阶段连续 60 秒匹配不到任何可执行页面（`ea_flow.IDLE_TIMEOUT_SECONDS`）也会判超时。
- **进度显示 `账号信息有误：<字段>`** — EA 在登录页给出了红字错误提示（字段名告诉你大概是哪一项：`EA邮箱` / `EA密码` / `EA 2FA 16位码`）。该账号已自动打上跳过标记、后续轮次不再跑它。核对 CSV 里对应字段，改好后右键 **“取消跳过标记”** 恢复（改账密本身不会取消标记）。
- **某个账号卡在登录页很久** — 同一页面连续重复 3 次仍未跳转就会停下换下一个账号（`ea_flow.LOGIN_STRATEGY_MAX_ATTEMPTS`），不会无限空转。日志里搜“连续 3 次未进入下一步”能看到是哪个页面卡住；这种情况没有红字证据，所以按普通失败上报、不自动打跳过标记，由你判断是否手动标记。
- **日志里出现“Steam窗口检测到红字”** — 这是线索不是结论（Steam 窗口里红色元素太多，整窗扫描精度不够，所以只记日志）。如果确认 Steam 账密写错了，右键该账号 →“标记为信息有误”。
- **报“未出现EA登录页就直接到达关联页”** — 这是故意拦下来的：EA 里还登录着别的账号（多半是上一个账号的登录态没清干净，或 EA 没被真正结束），流程没让你填邮箱/密码就走到关联页，硬点下去会把 Steam 账号绑到错误的 EA 账号上。注意这与“停在换号页”是两回事：停在 `Confirm your EA Account` 换号页时程序会自己点 “Not your account?” 登出重来（状态显示 `EA切换账号中`），不需要人工干预；只有连换号页都没出现、直接跳到 `Link your EA Account to Steam` 才会报这个错。遇到就确认 EA 已退出登录（必要时手动退出一次）后重跑该账号；若确认这个 EA 账号就是对的，可以右键“标记为已绑定”跳过。
- **卡在“校验关联结果中”然后报超时** — 先在日志里搜“关联账号”，看三件事：点击时窗口有没有确认到前台（出现“未确认到前台”说明被别的窗口挡住了）、点击的屏幕坐标是否落在按钮上、以及有没有“页面未跳转，重新点击”。再打开同目录下 `*_link_clicked_printwindow.png`，如果图里关联页还在，说明点击确实没被 EA 接收，而不是 EA 反应慢。这类情况多半是别的窗口（包括本工具自己的界面）压在前面，运行期间不要动鼠标键盘、也不要把窗口拖到 EA 上面。

## 安全提醒

- CSV 里是**明文密码**，请妥善保管，不要随意外发或提交到仓库。
- 界面默认掩码敏感字段，离开电脑时注意不要点“显示密码/16位码”。
- 本工具通过模拟人工操作完成绑定，请遵守 Steam、EA 的服务条款，账号风险自负。
